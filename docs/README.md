# 業務工数システム 引き継ぎ教育資料

このフォルダ（`docs/`）には、本Webアプリ「業務工数システム」を **作成・運用・保守** していくために必要な知識を、**プログラミング完全初心者** でも学べるようにまとめた教育資料が入っています。

---

## 0. この資料の対象読者

- これまでプログラミングをほとんど（あるいは全く）やったことがない方
- このアプリの保守・運用を引き継ぐことになった方
- 「何から手をつければいいか分からない」という状態の方

専門用語には初出のときに必ず説明を入れています。サンプルコードは原則 **1行ずつコメント** を付けています。分からない単語が出てきたら、まず巻末の「[10_用語集](./10_用語集.md)」を引いてください。

---

## 1. このアプリは何をするもの？（30秒で理解）

工場などの現場で、従業員が **「いつ・どの作業に・何時間使ったか（＝工数）」** を記録・集計するためのWebアプリです。

- 従業員が自分の作業時間を入力する
- 休憩時間を差し引いて正味の工数を自動計算する
- 班（チーム）単位・ショップ（職場）単位で集計・グラフ表示する
- 管理者がデータのバックアップ・復元、操作履歴の確認を行う

詳しくは「[00_導入と全体像](./00_導入と全体像.md)」で説明します。

## 2. 技術構成（ざっくり）

```
        ブラウザ（利用者）
            │  画面操作
            ▼
┌───────────────────────────┐
│ フロントエンド             │  React + TypeScript
│ （見た目・画面の動き）       │  ＝ frontend/ フォルダ
└───────────────────────────┘
            │  API通信（HTTP / JSON）
            ▼
┌───────────────────────────┐
│ バックエンド               │  Django + Django REST Framework
│ （データ処理・業務ロジック） │  ＝ kosu/ ・ hozen_another/ フォルダ
└───────────────────────────┘
            │  SQL
            ▼
┌───────────────────────────┐
│ データベース               │  PostgreSQL
│ （データの保存場所）         │
└───────────────────────────┘
```

「フロントエンド」「バックエンド」「API」などの言葉が分からなくても大丈夫です。後の資料で順を追って説明します。

## 4. 学習ロードマップ（目安）

完全初心者を想定した、無理のない進め方の目安です。**焦らず、手を動かしながら** 進めてください。

### フェーズ1：まず動かす（1〜2週間）
0. パソコン操作に不安があれば、まず `00a`（超入門）を読む
1. `00` を読んで全体像をつかむ（理解できなくてもOK、雰囲気をつかむ）
2. `01` を読みながら、自分のPCに開発環境を作る
3. `02` を読みながら、GitHubからコードを取得（クローン）できるようにする
4. アプリをローカル（自分のPC）で起動して、画面を触ってみる

> ✅ ゴール：自分のPCで `npm start` と `python manage.py runserver` を実行し、ブラウザでアプリが表示できる。

### フェーズ2：言語の基礎（2〜4週間）
5. `03`（HTML/CSS）→ `04`（JS/TS）→ `06`（Python）を読む
6. 実際のコードを開いて「これはあの文法だな」と照らし合わせる

> ✅ ゴール：本アプリのコードを開いたとき、「何が書いてあるか雰囲気が読める」。

### フェーズ3：フレームワークと本アプリの構造（3〜6週間）
7. `05`（React）と `07`（Django）を読む
8. `08`（データベース・モデル）でデータ構造を理解する
9. 小さな修正（文言の変更など）を試してみる

> ✅ ゴール：「この画面のこの文字を変えたい」を自力で実現できる。

### フェーズ4：運用・保守(継続)
10. `09` を読み、バックアップ・復元・デプロイを実際に練習する

> ✅ ゴール：本番環境を壊さずに、運用作業とリリースができる。

## 5. この資料の使い方のコツ

- **分からない単語はすぐ調べる**：まず `10_用語集` 、なければ検索（「○○ とは」で調べると初心者向け解説が出ます）。
- **コードは写経する**：読むだけでなく、自分で打ち込むと身につきます。
- **壊しても大丈夫な環境で練習する**：ローカル環境やテスト用データで試し、いきなり本番を触らない（理由は `09` で説明）。
- **エラーは敵ではない**：エラーメッセージは「どこが悪いか」を教えてくれる味方です。メッセージをそのまま検索しましょう。
